Signals
signal<T>(initialValue: T): Signal<T>
Creates a reactive signal. The returned function reads the current value; .set() updates it and notifies all subscribers. Pass an updater function to .set() for atomic updates based on previous value.
computed<T>(fn: () => T): ComputedSignal<T>
Creates a lazily-evaluated, memoized derived signal. The computation runs when first read and whenever any of its signal dependencies change. Read-only — has no .set() method.
effect(fn: () => void | (() => void)): Unsubscribe
Runs fn immediately and re-runs it whenever any signal read inside it changes. If fn returns a function, that cleanup function is called before the next run. Returns a dispose function to stop the effect.
batch(fn: () => void): void
Groups multiple signal writes into a single notification pass. Effects and computed signals that depend on the written signals will only re-run once after the batch completes, not after each individual write.
untrack<T>(fn: () => T): T
Executes fn without tracking any signal reads inside it. Useful to read signal values in an effect or computed without creating dependencies on those signals.
createStore<T>(initialState: T): Store<T>
Creates a deeply nested reactive store. Each leaf property becomes an individual signal, enabling fine-grained reactivity. Updates to nested paths only notify dependents of that specific path.
label<T>(name: string, sig: Signal<T>): Signal<T>
Attaches a debug label to a signal. Labeled signals appear in devtools, _getDevSignals(), audit logs, and session replay events. Returns the same signal with the label applied.
Renderer
h(tag: string | Component, props: Props, ...children: Children): Node
Creates a reactive DOM node. Props and children can be functions — when they are, DRISHTI creates fine-grained subscriptions that update only the specific DOM attribute or text node when the referenced signal changes. No virtual DOM diffing.
text(value: string | (() => string)): Text
Creates a reactive text node. If value is a function, re-runs whenever its signal dependencies change, updating only the text content.
show(condition: () => boolean, truthy: Node, falsy?: Node): Node
Conditionally renders one of two subtrees based on a reactive condition. Mounts/unmounts the appropriate subtree — does not use CSS display toggling. The falsy argument is optional.
each<T>(list: Signal<T[]>, renderItem: (item: T, index: number) => Node): Node
Renders a reactive list with keyed reconciliation. When the list signal updates, DRISHTI diffs by key and only adds, removes, or moves DOM nodes as needed — existing nodes are never unnecessarily recreated.
portal(target: Element, content: Node): Node
Renders content into target rather than the current mount position. Useful for modals, tooltips, and popovers that need to escape stacking contexts. The portal is cleaned up when the parent is unmounted.
mount(component: Component, container: Element): () => void
Mounts a component into a container element. Returns an unmount function. Lower-level than mountApp — does not set up devtools or global signal registry.
mountApp(App: Component, container: Element, options?: MountOptions): () => void
Mounts the root application component. Sets up the global signal context, devtools integration (if enabled), and returns an unmount function. This is the primary entry point for DRISHTI applications.
Dev & AI Agent APIs
_enableDevMode(): void
Enables development mode globally. Activates the signal registry, performance tracking, devtools panel integration, and verbose error messages. Call once before mounting your app.
_getDevSignals(): Record<string, Signal<unknown>>
Returns a map of all labeled signals currently registered in the application. Keys are the label strings. This is the primary API for AI agents to read and write application state — call .set() on any returned signal to update the UI instantly.
_setSignalWriteHook(fn: (label: string, prev: unknown, next: unknown) => void): () => void
Registers a global hook called on every signal write. Receives the signal label, previous value, and new value. Ideal for AI agent observation, logging, and debugging. Returns a cleanup function. Only fires for labeled signals.
_totalEffectRuns(): number
Returns the total number of effect executions since _enableDevMode() was called. Use to profile reactivity performance and detect unnecessary re-runs.
_setSSRMode(enabled: boolean): void
Switches DRISHTI into SSR mode. Effects and subscriptions are disabled; signals are read-only statics. Used internally by @drishti/ssr for server-side rendering.
Time Travel
enableTimeTravel(options?: TimeTravelOptions): TimeTravelHandle
Activates the time-travel debugging system. Records every signal write as a TimeTravelEntry. Returns a handle with snapshot(), restore(), back(), forward(), entries(), and replay() methods. Option maxEntries (default 200) limits history size.
const _ttState: Signal<TimeTravelEntry[]>
Reactive signal containing the current time-travel history stack. Reading this in UI code will re-render when entries are added or removed, enabling reactive time-travel UIs.
Animation
spring(target: Signal<number>, config?: SpringConfig): SpringSignal
Creates a spring-physics animated signal that follows the target signal with configurable stiffness and damping. The returned signal's value smoothly transitions toward the target. Config: { stiffness, damping, mass, precision }.
tween(target: Signal<number>, config?: TweenConfig): TweenSignal
Creates a tween-animated signal with configurable duration and easing function. Config: { duration, easing, delay }. Use with Easing for built-in curves.
stagger(signals: Signal<number>[], delay: number): Signal<number>[]
Returns animated versions of each input signal, staggered by the given delay in milliseconds. Useful for list entrance animations.
interpolate(t: number, a: number, b: number): number
Linear interpolation between two values. t=0 returns a, t=1 returns b. Useful for custom animation calculations.
const Easing: { linear, easeIn, easeOut, easeInOut, bounce, elastic, ... }
Collection of standard easing functions for use with tween(). Each is a function (t: number) => number where t is progress from 0 to 1.
State Machines
createMachine<S, E>(config: MachineConfig<S, E>): MachineHandle<S, E>
Creates a typed, reactive state machine. Config requires initial state and states map. Each state can define on (event transitions), entry/exit actions, meta data, and guard functions. Returns a handle with state() signal, send(event), can(event), and history().
Healing & Resilience
class HealingMonitor(config: HealConfig)
Monitors application health and automatically attempts recovery from detected anomalies. Tracks signal write failures, effect throws, and rendering errors. Configures heal strategies: retry, reset, fallback, or custom.
class CircuitBreaker(config: CircuitBreakerConfig)
Implements the circuit breaker pattern for async operations. States: closed (normal), open (failing fast), half-open (testing recovery). Config: { threshold, timeout, halfOpenRequests }.
createErrorBoundary(options: ErrorBoundaryOptions): ErrorBoundary
Creates a reactive error boundary that catches rendering and effect errors in its subtree. Renders a fallback UI on error and exposes error() signal and reset() method.
Security
class ZeroTrustMesh(config: SecureConfig)
Implements zero-trust security mesh for signal access. Enforces per-signal read/write permissions based on current authentication context, role, and request origin.
mesh(signal: Signal<T>, policy: SecurityPolicy): Signal<T>
Wraps a signal with a zero-trust security policy. Reads and writes are intercepted and evaluated against the policy. Throws SecurityError on policy violations.
sanitizeHTML(html: string): string
Sanitizes an HTML string, removing dangerous tags and attributes (scripts, event handlers, data URIs). Uses an allowlist-based approach for safe inner HTML rendering.
sanitizeURL(url: string): string
Validates and sanitizes a URL, blocking javascript:, data:, and other dangerous schemes. Returns an empty string if the URL is unsafe.
sanitizeInput(value: string): string
Sanitizes user input by escaping HTML entities and removing control characters. Use for any user-provided text that will be rendered in the DOM.
sanitizeObject<T>(obj: T): T
Recursively sanitizes all string values in an object using sanitizeInput. Safe for processing API responses or form data before storing in signals.
Integration / Connectors
connect(config: DataConfig): ConnectorState
Generic connector factory. Supports REST, WebSocket, and SSE transports. Returns reactive signals for data, status, error, and a send() function.
connectREST(url: string, options?: RequestInit): ConnectorState
Creates a reactive REST endpoint connector. Automatically refetches on signal dependency changes. Supports polling with options.interval.
connectWS(url: string): ConnectorState
Creates a WebSocket connector with automatic reconnection and exponential backoff. Exposes data(), status(), and send() as reactive primitives.
connectSSE(url: string): ConnectorState
Creates a Server-Sent Events connector. Parses event types and data automatically. Reconnects with configurable retry logic.
Router
createRouter(routes: RouteConfig[], options?: RouterOptions): Router
Creates a client-side router with hash or history mode. Routes support parameters (:id), wildcards, redirects, and async route guards. Returns reactive location(), params(), and query() signals.
useRouter(): Router
Returns the active router instance. Throws if no router has been set with setActiveRouter() or mountApp().
createFileRouter(options: FileRouterOptions): FileRouterHandle
Filesystem-based routing similar to Next.js. Scans the pages directory and generates routes automatically. Integrates with the Vite plugin for zero-config setup.
Forms
createForm<T>(schema: FieldSchema<T>): Form<T>
Creates a reactive form with per-field validation, touched/dirty tracking, and async validators. Schema defines field defaults and validator functions. Returns fields with individual signals, valid(), dirty(), and submit(handler).
Performance
memo<T>(fn: () => T, deps?: Signal<unknown>[]): () => T
Memoizes the return value of fn. If explicit deps are provided, recomputes only when those signals change. Otherwise behaves like computed.
debounce<T>(signal: Signal<T>, ms: number): Signal<T>
Returns a new signal that debounces updates from the source signal by ms milliseconds. Useful for search inputs and resize handlers.
throttle<T>(signal: Signal<T>, ms: number): Signal<T>
Returns a new signal that throttles updates to at most once every ms milliseconds. Useful for scroll and mousemove events.
distinct<T>(signal: Signal<T>, eq?: (a: T, b: T) => boolean): Signal<T>
Returns a new signal that only emits when the value actually changes. Uses === by default; pass a custom equality function for deep comparison.
virtual<T>(items: Signal<T[]>, config: VirtualListConfig): VirtualList<T>
Creates a virtualized list that only renders visible items. Config: { itemHeight, containerHeight, overscan }. Returns signals for visibleItems() and totalHeight().
lazy<T>(loader: () => Promise<T>): Signal<T | null>
Creates a lazily-loaded signal. loader is called on first read and the signal updates with the resolved value. Handles loading and error states reactively.
fromEvent<E>(target: EventTarget, event: string): Signal<E | null>
Creates a signal from a DOM event. Updates with the latest event object each time the event fires. Automatically removes the listener when the signal is disposed.
Async Resources
createResource<T, S>(source: Signal<S>, fetcher: (source: S) => Promise<T>, options?: ResourceOptions): [Resource<T>, { refetch: () => void }]
Creates a reactive async resource. Re-fetches automatically when the source signal changes. Returns a resource signal with .loading(), .error(), and the data itself. Supports SSR initial data and optimistic updates.
createMutation<T, V>(options: MutationOptions<T, V>): Mutation<T, V>
Creates an imperative mutation helper with reactive status. Options: mutationFn, onSuccess, onError, onSettled. The returned handle has mutate(), loading(), error(), and data().
createCache<V>(options: CacheOptions): Cache<string, V>
Creates a reactive in-memory cache with TTL, LRU eviction, and signal integration. Methods: get(key), set(key, value), invalidate(key), clear(). Cache hits are reactive — dependents update when a key changes.
Query
createQuery<T>(options: QueryOptions<T>): QueryResult<T>
Data fetching with automatic caching, background refresh, and deduplication. Options: key (reactive cache key), fetcher, staleTime, refetchOnFocus, refetchInterval. Returns data(), loading(), error(), refetch().
createQueryMutation<T, V>(options: MutationOptions): MutationResult<T>
Mutation helper that integrates with the query cache. Automatically invalidates or updates related queries on success.
invalidateQuery(key: unknown[]): Promise<void>
Marks all queries matching the given key prefix as stale and triggers a background refetch. Use after mutations to keep data fresh.
invalidateAllQueries(): Promise<void>
Marks all active queries as stale and refetches them. Useful after logout or global state resets.
Internationalization
createI18n(options: I18nOptions): I18nInstance
Creates a reactive i18n instance. Options: locale (signal or string), messages (catalog), fallbackLocale. Returns t(key, params?) translation function and locale() signal. Switching locale reactively updates all translations.
Persistence
persistSignal<T>(key: string, signal: Signal<T>, options?: PersistOptions): PersistedSignal<T>
Persists a signal to localStorage (or a custom storage adapter). Automatically restores on page load and syncs writes to storage. Options: storage, serialize, deserialize, version (for migrations).
createPersistedStore<T>(key: string, initial: T): PersistedStore<T>
Creates a store whose entire state is persisted to localStorage as a single JSON entry. The store is hydrated on init. Supports schema versioning and migration functions.
Collaborative
createCollabSession(options: CollabOptions): CollabHandle
Creates a CRDT-backed collaborative session over WebSockets. Options: room, transport, userId, presence. Returns signal(key, initial) to create shared signals, presence() for connected users, and status(). Uses vector clocks for conflict resolution — all operations are commutative and idempotent.
Islands Architecture
defineIsland(name: string, component: Component, options?: IslandOptions): IslandDefinition
Defines a component as a client-side island. Options include hydration strategy: 'eager' (immediate), 'lazy' (on import), 'viewport' (IntersectionObserver), 'idle' (requestIdleCallback).
hydrateIslands(manifest?: IslandManifest): void
Scans the document for server-rendered island placeholders and hydrates them according to each island's hydration strategy. Called automatically by the SSR runtime; call manually for progressive enhancement.
getIslandRegistry(): Map<string, IslandDefinition>
Returns the registry of all defined islands. Used by the Vite plugin to generate island bootstrap code and code-split bundles.
generateIslandBootstrap(manifest: IslandManifest): string
Generates the minimal JavaScript bootstrap snippet for island hydration. Emitted by the Vite plugin into the HTML output.
LLM Streaming
createLLMStream(options: LLMStreamOptions): LLMStreamHandle
Creates a reactive LLM streaming connection. Options: endpoint, model, headers. Handle exposes text() (streamed content), status() ('idle'|'streaming'|'done'|'error'), tokens() (count), and send(payload). Supports Anthropic, OpenAI, and custom streaming formats.
createThinkingState(): ThinkingState
Creates reactive signals for extended thinking visualization. Tracks when the model is in the thinking phase, the thinking content, and thinking duration. Use with createLLMStream for Claude extended thinking.
createToolCallState(): ToolCallState
Tracks active tool calls during LLM streaming. Returns reactive signals for current tool calls, their arguments, and execution state. Useful for showing tool use progress in the UI.
Feature Flags & A/B Testing
createFlag(config: FlagConfig): FlagHandle
Creates a reactive feature flag. Config: key, defaultValue, variants. The flag value is a reactive signal that updates when the flag configuration changes. Supports percentage rollouts, user targeting, and custom rules.
createFlagStore(flags: Record<string, FlagConfig>): Signal<Record<string, FlagVariant>>
Creates a store of multiple feature flags. The returned signal contains the resolved variant for each flag key. Updates reactively when any flag changes.
createBandit(options: BanditOptions): BanditHandle
Multi-armed bandit for adaptive A/B testing. Implements epsilon-greedy, UCB1, or Thompson Sampling algorithms. Automatically converges on the best performing variant over time.
createAutoRollout(options: AutoRolloutOptions): AutoRolloutHandle
Automated feature rollout with configurable gates. Monitors error rates, performance metrics, and custom signal conditions — automatically pauses rollout if thresholds are exceeded.
createRateLimitedFlag(options: RateLimitedFlagOptions): FlagHandle
Feature flag with built-in rate limiting. Limits the number of times a flag can evaluate to true within a time window. Useful for beta feature access limits.
Session Replay
createSessionReplay(options: ReplayOptions): ReplayHandle
Records user sessions including signal mutations, DOM events, and network requests. Generates a compact replay bundle that can be played back for debugging. Options: endpoint, sampleRate, maskFields (for PII redaction), maxDuration.
OpenTelemetry
createOtelTracer(options: OtelOptions): OtelHandle
Integrates with OpenTelemetry for distributed tracing. Automatically instruments signal effects and async operations as spans. Options: serviceName, endpoint, sampler. Returns tracer for manual span creation.
Error Tracking
createErrorTracker(options: ErrorTrackingOptions): ErrorTrackingHandle
Captures and reports JavaScript errors, unhandled promise rejections, and DRISHTI effect errors. Options: endpoint, sampleRate, beforeSend (filter/enrich hook). Returns errors() reactive signal and capture(error) method.
PWA & Offline
createPWA(options: PWAOptions): PWAHandle
Sets up Progressive Web App infrastructure: service worker registration, update notification, and install prompt management. Returns reactive updateAvailable(), installed(), and online() signals.
createOfflineQueue(options: OfflineQueueOptions): OfflineQueueHandle
Queues operations when offline and replays them when connectivity is restored. Supports ordered execution, retry limits, and conflict resolution strategies.
Content Security Policy
createCSP(options: CSPOptions): CSPHandle
Generates and applies Content Security Policy headers or meta tags. Supports nonce injection for inline scripts, automatic hash generation for static assets, and violation reporting. Returns nonce() reactive signal for safe inline script execution.
HIPAA
enableHIPAA(config: { encryptionKey: string, auditEndpoint: string, phiSignals: Signal[] }): void
Enables HIPAA compliance mode. Encrypts all designated PHI signals at rest, enforces access logging, disables devtools for sensitive signals, and activates mandatory audit trail for all PHI reads and writes.
Audit Logging
createAuditLog(options: { endpoint: string, signals?: Signal[] }): { log: (action: string, meta?: object) => void }
Creates an immutable, tamper-evident audit log. Entries are cryptographically chained (each entry hashes the previous). Automatically logs writes to watched signals. The log() method creates manual entries with action type and arbitrary metadata.
Consent Management
createConsentManager(options: ConsentOptions): ConsentHandle
GDPR-compliant consent manager. Stores consent in localStorage, presents a configurable consent banner, and exposes has(category) reactive checks. Supports IAB TCF 2.0 integration. Categories: 'analytics', 'marketing', 'functional', or custom.
Real User Monitoring
createRUM(options: RUMOptions): RUMHandle
Collects Core Web Vitals (LCP, FID, CLS, TTFB, INP) and custom metrics. Reports to the configured endpoint at sample rate. Returns reactive vitals() signal for real-time dashboards. Integrates with OpenTelemetry for correlation.
Deploy Adapters
generateVercelConfig(options: DeployConfig): VercelConfig
Generates a Vercel deployment configuration object. Handles SSR routes, edge functions, ISR settings, and headers. Pass to generateVercelJson() to write vercel.json.
generateNetlifyConfig(options: DeployConfig): NetlifyConfig
Generates a Netlify deployment configuration. Handles redirects, edge functions, and build settings. Pass to generateNetlifyToml() to write netlify.toml.
generateCloudflareConfig(options: DeployConfig): CloudflareConfig
Generates a Cloudflare Workers/Pages deployment configuration including D1, KV, R2 bindings, and worker routes. Pass to generateWranglerToml() to write wrangler.toml.
generateVercelJson(config: VercelConfig): string
Serializes a VercelConfig object to a vercel.json formatted string. Write to disk with fs.writeFileSync('vercel.json', result).
generateNetlifyToml(config: NetlifyConfig): string
Serializes a NetlifyConfig object to a netlify.toml formatted string.
generateWranglerToml(config: CloudflareConfig): string
Serializes a CloudflareConfig object to a wrangler.toml formatted string for Cloudflare Workers deployment.
Hot Module Replacement
captureSignalState(): HMRSignalState
Captures the current values of all labeled signals. Called by the Vite plugin before a hot module swap to preserve state across updates.
restoreSignalState(state: HMRSignalState): void
Restores signal values from a previously captured state snapshot. Called by the Vite plugin after a hot module swap to resume from the preserved state.
createHMRPlugin(options?: HMROptions): VitePlugin
Creates a Vite HMR plugin that preserves DRISHTI signal state across hot module replacements. Included by default in @drishti/vite-plugin.
Cloudflare Bindings
createD1Signal(db: D1Database, query: string, options?: D1SignalOptions): D1SignalHandle
Creates a reactive signal backed by a Cloudflare D1 SQL query. The signal updates when the query result changes. Supports parameterized queries and automatic polling.
createKVSignal(kv: KVNamespace, key: string, options?: KVSignalOptions): KVSignalHandle
Creates a reactive signal backed by a Cloudflare KV namespace key. Reads from KV on init and provides .set() that writes through to KV. Supports TTL and metadata.
Optimistic Updates
createOptimistic<T>(signal: Signal<T>, options?: OptimisticOptions): OptimisticHandle<T>
Wraps a signal with optimistic update behavior. optimisticSet(value) immediately updates the signal; if the async operation fails, automatically rolls back to the previous value. Handles concurrent updates safely.
Intent Engine
createIntentEngine(options: IntentEngineOptions): IntentEngine
Analyzes signal mutation patterns to infer user intent. Classifies actions (navigate, search, create, delete, etc.) from sequences of signal writes. Primary API for AI agents to understand what the user is trying to accomplish.
useIntent(): Signal<UserIntent | null>
Returns a reactive signal containing the currently detected user intent. Updates as the intent engine processes new signal mutations.
Stories & Playground
story(name: string, definition: StoryDefinition): StoryHandle
Defines a component story for the DRISHTI playground. Stories describe component variants with props and signal states. Registered stories are discoverable via getStories().
getStories(): StoryDefinition[]
Returns all registered story definitions. Used by the playground and testing utilities to enumerate component variants.
clearStories(): void
Clears all registered stories. Used in test environments to reset state between test suites.
launchPlayground(options?: PlaygroundOptions): void
Launches the interactive DRISHTI playground in a browser window. Displays all registered stories with live signal editing, time-travel controls, and component inspector.
Resilience
circuit(fn: () => Promise<T>, options: CircuitOptions): CircuitHandle
Wraps an async function with circuit breaker logic. Tracks failure rate and trips the circuit after the configured threshold. Returns a reactive state() signal and execute() method.
withFallback<T>(signal: Signal<T>, fallback: T): Signal<T>
Returns a derived signal that returns fallback when the source signal is null, undefined, or throws. Useful for graceful degradation.
retry<T>(fn: () => Promise<T>, policy: RetryPolicy): Promise<T>
Retries a promise-returning function according to the given policy. Policy options: maxAttempts, delay, backoff ('linear'|'exponential'), shouldRetry (predicate on error).
timeout<T>(promise: Promise<T>, ms: number): Promise<T>
Races a promise against a timeout. Throws a TimeoutError if the promise does not resolve within ms milliseconds.
Server Functions & Signals
createServerFn<T, A>(fn: (args: A) => Promise<T>, options?: ServerFnOptions): ServerFnHandle<T, A>
Creates a type-safe server function callable from the client. Handles serialization, error propagation, and optional optimistic updates. The Vite plugin transforms calls to use the appropriate RPC mechanism.
createServerSignal<T>(options: ServerSignalOptions<T>): ServerSignalHandle<T>
Creates a signal pushed from the server via WebSocket or SSE. Supports bidirectional sync — writes on the client can optionally propagate back to the server.
createSSESignal<T>(options: SSESignalOptions<T>): SSESignalHandle<T>
Creates a read-only signal fed by a Server-Sent Events stream. Automatically parses typed event data and handles reconnection with exponential backoff.
Edge Runtime
detectPlatform(): 'cloudflare' | 'vercel' | 'netlify' | 'deno' | 'node' | 'browser'
Detects the current runtime environment by inspecting global variables and API availability. Returns a string identifier for the detected platform.
createEdgeHandler(App: Component, options: EdgeRenderOptions): EdgeContext
Creates a platform-agnostic edge handler for server-side rendering. Handles streaming HTML response, initial state injection, and platform-specific request/response adaptations.
injectState(html: string, state: Record<string, unknown>): string
Injects serialized signal state into an HTML string as a JSON script tag for client hydration. Used in SSR pipelines to pass server state to the browser.
mergeHeaders(...headers: HeadersInit[]): Headers
Merges multiple header objects into a single Headers instance. Later headers override earlier ones for duplicate keys. Utility for edge handler composition.
tRPC Adapter
createTRPCQuery<T>(options: TRPCQueryOptions<T>): TRPCQueryHandle<T>
Creates a reactive tRPC query. Wraps tRPC procedure calls in DRISHTI's reactive query system with caching, loading states, and automatic re-fetching when dependencies change.
createTRPCMutation<T, V>(options: TRPCMutationOptions): TRPCMutationHandle<T>
Creates a reactive tRPC mutation. Handles loading state, error capture, and automatic query invalidation on success.
GraphQL Adapter
createGraphQLQuery<T>(options: GraphQLOptions): GraphQLHandle<T>
Creates a reactive GraphQL query. Options: query (document), variables (signal-compatible), endpoint, headers. Supports subscriptions via WebSocket transport. Variables can be signals — the query re-runs automatically when they change.
Adaptive Signals
createAdaptSignal<T>(options: AdaptOptions<T>): AdaptSignal<T>
Creates a signal that adapts its value based on observed user behavior and feedback. Uses a reinforcement learning model to converge on the value that maximizes a configured reward signal. Useful for personalization and adaptive UIs.
useAdaptSignal<T>(signal: AdaptSignal<T>): { value: Signal<T>, observe: (reward: number) => void }
Consumes an adaptive signal in a component. Returns the current value and an observe(reward) function to provide feedback that shapes future adaptations.
Genome (Design Tokens)
loadGenome(config: GenomeConfig): void
Loads a genome design token configuration. Applies CSS custom properties to the document root and registers tokens for reactive access via useGenome().
loadGenomePreset(preset: keyof typeof GenomePresets): void
Loads one of the built-in genome presets: 'default', 'minimal', 'playful', 'enterprise'. Shorthand for loadGenome(GenomePresets[preset]).
useGenome(): Signal<GenomeConfig>
Returns a reactive signal containing the currently active genome configuration. Updates when the genome is changed, triggering reactive re-renders of genome-dependent components.
generatePalette(baseColor: string): ColorPalette
Generates a complete 11-shade color palette from a single base hex color. Uses perceptually uniform color space (OKLCH) for consistent lightness distribution.
applyEmotionAdaptation(state: EmotionState): void
Adapts the active genome to reflect an emotional state. Modifies color temperature, contrast, and animation timing to match the emotion (calm, energetic, focused, playful).
