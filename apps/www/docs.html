Getting Started

Installation

Get DRISHTI up and running in under 2 minutes.

Create a new project

The fastest way to start is with the official scaffolding tool:

npm create drishti-app@latest my-app
cd my-app && npm install && npm run dev

This sets up a full project with TypeScript, Vite, testing, and hot module replacement preconfigured.

Add to existing project

Install the runtime package directly:

npm install @drishti/runtime

Manual Vite setup

// vite.config.ts
import { drishti } from '@drishti/vite-plugin';

export default {
  plugins: [drishti()],
};

TypeScript config

{
  "compilerOptions": {
    "strict": true,
    "moduleResolution": "bundler",
    "target": "ES2022"
  }
}
Tip: DRISHTI requires moduleResolution: "bundler" or "node16" to correctly resolve .js imports in TypeScript.
Getting Started

Quick Start

Build your first DRISHTI app in minutes.

Your first signal

Signals are the core reactive primitive in DRISHTI. A signal holds a value and notifies subscribers when it changes.

import { signal, effect, computed } from '@drishti/runtime';

const name = signal('World');

effect(() => {
  console.log(`Hello, ${name()}!`);
});
// Logs: "Hello, World!"

name.set('DRISHTI');
// Logs: "Hello, DRISHTI!"

Mount an app

Use h() to describe UI and mountApp() to attach it to the DOM:

import { signal, h, mountApp } from '@drishti/runtime';

const count = signal(0);

const App = () => h('div', {},
  h('p', {}, () => `Count: ${count()}`),
  h('button', { onclick: () => count.set(count() + 1) }, '+'),
);

mountApp(App, document.getElementById('app'));
Getting Started

Vite Setup

Configure DRISHTI with Vite for the best development experience.

Install the plugin

npm install -D @drishti/vite-plugin

Configure Vite

// vite.config.ts
import { defineConfig } from 'vite';
import { drishti } from '@drishti/vite-plugin';

export default defineConfig({
  plugins: [
    drishti({
      islands: true,       // Enable island extraction
      hmr: true,           // Signal-aware HMR
      devtools: true,      // Browser devtools panel
    }),
  ],
});

Features

  • HMR: Full hot module replacement with signal state preservation via captureSignalState / restoreSignalState.
  • .dr Files: Single-file component format with styles, template, and logic co-located.
  • Island Extraction: Automatic detection and code-splitting of island components.
  • Dev Tools: Browser panel showing all labeled signals and their current values in real time.

Core

Signals

The fundamental reactive primitive. A signal holds a value and notifies all dependents when it changes.

Creating a signal

Call signal(initialValue) to create a reactive cell. The return value is both a getter function and has a .set() method.

import { signal } from '@drishti/runtime';

const count = signal(0);
const user  = signal<User | null>(null);
const items = signal<string[]>([]);

Reading and writing

// Read: call as a function
console.log(count());   // 0

// Write: use .set()
count.set(5);
count.set(prev => prev + 1);  // Updater function

// Check current value
console.log(count());   // 6

Subscribing with effect()

An effect runs immediately and re-runs whenever any signal it reads changes.

import { effect } from '@drishti/runtime';

const dispose = effect(() => {
  console.log('count is now', count());
});
// Runs immediately: "count is now 6"

count.set(10);
// Runs again: "count is now 10"

// Stop tracking
dispose();

Computed signals

Derived values that update automatically when their dependencies change:

import { computed } from '@drishti/runtime';

const price    = signal(100);
const quantity = signal(3);
const total    = computed(() => price() * quantity());

console.log(total()); // 300
price.set(150);
console.log(total()); // 450

Batching multiple updates

Use batch() to group multiple signal writes into a single notification pass:

import { batch } from '@drishti/runtime';

batch(() => {
  firstName.set('Jane');
  lastName.set('Doe');
  age.set(30);
});
// Effects run once, not three times
Core

Computed Signals

Lazily-evaluated, memoized derived values. Recomputes only when dependencies change.

Basic usage

const firstName = signal('Alice');
const lastName  = signal('Smith');
const fullName  = computed(() => `${firstName()} ${lastName()}`);

// fullName() is lazily computed and cached
console.log(fullName()); // "Alice Smith"

Computed chains

Computed signals can depend on other computed signals, forming reactive dependency graphs:

const items       = signal([1, 2, 3, 4, 5]);
const multiplier  = signal(2);
const scaled      = computed(() => items().map(x => x * multiplier()));
const sum          = computed(() => scaled().reduce((a, b) => a + b, 0));
Core

Effects

Run side effects that automatically track and re-run on signal changes.

Basic effect

const dispose = effect(() => {
  document.title = `Count: ${count()}`;
});
// Call dispose() to stop the effect

Async effects

Effects can be async, but only the synchronous portion tracks dependencies:

effect(async () => {
  const userId = currentUser(); // tracked
  const data = await fetch(`/users/${userId}`).then(r => r.json());
  userData.set(data); // not tracked (after await)
});
Core

Batch & Untrack

Control when effects re-run and what signals they track.

batch()

Defer all effect notifications until the batch completes:

batch(() => {
  x.set(1); y.set(2); z.set(3);
}); // Effects run once here

untrack()

Read signal values without creating a dependency:

import { untrack } from '@drishti/runtime';

effect(() => {
  const a = trackThis(); // tracked
  const b = untrack(() => dontTrack()); // not tracked
  console.log(a, b);
});

Stores

Structured reactive state with nested signals for complex objects.

createStore()

import { createStore } from '@drishti/runtime';

const store = createStore({
  user: { name: 'Alice', age: 30 },
  settings: { theme: 'dark', lang: 'en' },
});

// Read nested properties reactively
console.log(store.user.name()); // 'Alice'

// Update a nested field — only that field's effects re-run
store.user.name.set('Bob');

Rendering

h()

Create reactive DOM nodes. No virtual DOM — updates go directly to the real DOM.

Basic usage

import { h } from '@drishti/runtime';

// h(tag, props, ...children)
const btn = h('button',
  { class: 'primary', onclick: () => doSomething() },
  'Click me'
);

Reactive props and children

Pass functions as props/children to make them reactive — they re-run when their signals change:

const color = signal('red');
const count = signal(0);

h('div',
  { style: () => `color: ${color()}` },
  () => `Count: ${count()}`  // updates without re-rendering the div
);

show()

Conditionally render content based on a reactive condition.

State

createMachine

XState-inspired typed state machines, fully integrated with DRISHTI signals.

Basic machine

import { createMachine } from '@drishti/runtime';

const machine = createMachine({
  initial: 'idle',
  states: {
    idle:    { on: { START: 'loading' } },
    loading: { on: { SUCCESS: 'done', ERROR: 'failed' } },
    done:    { on: { RESET: 'idle' } },
    failed:  { on: { RETRY: 'loading', RESET: 'idle' } },
  },
});

machine.send('START');
console.log(machine.state()); // 'loading'

Guards and actions

createMachine({
  initial: 'idle',
  states: {
    idle: {
      on: {
        SUBMIT: {
          target: 'loading',
          guard: (ctx) => ctx.isValid,
          action: (ctx) => ctx.validate(),
        },
      },
    },
  },
});

enableTimeTravel

Record, snapshot, and restore complete application state for debugging.

Usage

import { enableTimeTravel } from '@drishti/runtime';

const tt = enableTimeTravel({ maxEntries: 100 });

// Snapshot current state
const snap = tt.snapshot();

// Make some changes...
count.set(99);

// Restore to snapshot
tt.restore(snap);

// Or step back through history
tt.back();
tt.forward();
tt.replay({ speed: 2 });

createResource

Async data fetching with loading, error, and success states as reactive signals.

Basic fetch

import { createResource } from '@drishti/runtime';

const userId = signal(1);
const [user, { refetch }] = createResource(
  userId,
  (id) => fetch(`/api/users/${id}`).then(r => r.json())
);

// user.loading() — boolean
// user.error()   — Error | null
// user()         — data | undefined

show(() => user.loading(), h('p', {}, 'Loading...'));
show(() => !user.loading(), h('p', {}, () => user()?.name));

Testing

Testing Utilities

First-class testing support for DRISHTI components and signals.

Install

npm install -D @drishti/testing

render()

import { render, expectSignal, takeSnapshot } from '@drishti/testing';
import { Counter } from './Counter';

test('counter increments', () => {
  const { container, signals } = render(Counter);
  expect(signals.count()).toBe(0);

  container.querySelector('button').click();
  expect(signals.count()).toBe(1);
});

auditA11y()

import { auditA11y } from '@drishti/testing';

test('no accessibility violations', async () => {
  const { container } = render(MyForm);
  const violations = await auditA11y(container);
  expect(violations).toHaveLength(0);
});

Deployment Overview

DRISHTI runs everywhere — Vercel, Netlify, Cloudflare Workers, and raw edge runtimes.

Generate config programmatically

import { generateVercelConfig, generateNetlifyConfig, generateCloudflareConfig } from '@drishti/runtime';

// Output ready-to-use config objects
const vercel = generateVercelConfig({ ssr: true, regions: ['iad1'] });
const netlify = generateNetlifyConfig({ edge: true });
const cf = generateCloudflareConfig({ d1: true, r2: true });
Deployment

Deploy to Vercel

Zero-config Vercel deployment with SSR, edge functions, and ISR support.

npm install @drishti/ssr
npx drishti build --target vercel

The Vite plugin automatically generates vercel.json and configures edge functions for SSR routes.

Deploy to Netlify

Full Netlify Edge Functions support with automatic netlify.toml generation.

npx drishti build --target netlify

Deploy to Cloudflare

Cloudflare Workers, D1, KV, and R2 — all with first-class DRISHTI bindings.

import { createD1Signal, createKVSignal } from '@drishti/runtime';

// D1 signal — SQLite-backed reactive value
