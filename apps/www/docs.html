Getting Started

Installation

DRISHTI is a TypeScript-first framework with zero external runtime dependencies.

Create a new project

The fastest way to start — scaffolds a full TypeScript app with Vite, HMR, and testing pre-configured:

npm create drishti-app@latest my-app
cd my-app
npm install
npm run dev

Add to existing project

Install only what you need. The runtime is the only required package — everything else is optional:

npm install @nexoraaidrishti/runtime
# Optional packages:
npm install @nexoraaidrishti/components       # UI components
npm install -D @nexoraaidrishti/vite-plugin   # .dr file support
npm install -D @nexoraaidrishti/testing       # testing utilities

Manual Vite setup

If you're adding to an existing Vite project, configure the plugin to enable .dr single-file components and HMR signal preservation:

// vite.config.ts
import { defineConfig } from 'vite';
import { drishti } from '@nexoraaidrishti/vite-plugin';

export default defineConfig({
  plugins: [drishti()],
});

TypeScript configuration

DRISHTI requires TypeScript 5.0+. Recommended tsconfig.json settings for optimal type inference:

{
  "compilerOptions": {
    "strict": true,
    "exactOptionalPropertyTypes": true,
    "moduleResolution": "bundler",
    "target": "ES2022"
  }
}
Tip: Run npx @nexoraaidrishti/cli doctor to verify your setup and diagnose any configuration issues.
Getting Started

Quick Start

Build your first reactive app in under 5 minutes.

Your first signal

Signals are the foundation of DRISHTI. A signal holds a value and notifies all subscribers when it changes. Read by calling it as a function, write with .set():

import { signal, effect } from '@nexoraaidrishti/runtime';

const name = signal('world');

effect(() => {
  console.log(`Hello, ${name()}!`);
});
// logs: Hello, world!

name.set('DRISHTI');
// logs: Hello, DRISHTI!

Your first component

Components are plain functions that return DOM nodes via h(). Reactive expressions in children re-run automatically when signals change:

import { signal, computed, h, mountApp } from '@nexoraaidrishti/runtime';

const count = signal(0);
const noun  = computed(() => count() === 1 ? 'click' : 'clicks');

function App() {
  return h('div', {},
    h('p', {}, () => `${count()} ${noun()}`),
    h('button', { onclick: () => count.set(count() + 1) }, 'Click me'),
  );
}

mountApp(App, document.getElementById('app')!);

Beta

.dr Single-File Components

Collocate script, template, and style in a single .dr file — compiled to pure signal calls at build time.

Example .dr file

A .dr file has three optional blocks: <script>, <template>, and <style>. The template is compiled to h() calls at build time:

<!-- Counter.dr -->
<script>
import { signal, computed } from '@nexoraaidrishti/runtime';
const count   = signal(0);
const doubled = computed(() => count() * 2);
</script>

<template>
  <div class="counter">
    <button :onclick="() => count.set(count() - 1)">-</button>
    <span>{{ count() }} (doubled: {{ doubled() }})</span>
    <button :onclick="() => count.set(count() + 1)">+</button>
  </div>
</template>

<style scoped>
.counter { display: flex; gap: 8px; align-items: center; }
</style>
Core

Signals

The reactive primitive at the heart of DRISHTI. Signals hold values and notify dependents synchronously when they change.

Creating signals

Call signal(initialValue) to create a reactive container. TypeScript infers the type from the initial value:

import { signal } from '@nexoraaidrishti/runtime';

const count   = signal(0);
const name    = signal('Alice');
const items   = signal<string[]>([]);
const user    = signal<{ id: number; role: string } | null>(null);

Reading and writing

Read a signal by calling it as a function. Reads inside effect() or computed() are automatically tracked:

// Read
console.log(count());     // 0

// Write with a new value
count.set(42);

// Functional update — read + write atomically
count.set(prev => prev + 1);
items.set(prev => [...prev, 'new item']);

Subscribing manually

For non-reactive contexts (analytics, logging), subscribe directly. Returns an unsubscribe function:

const unsub = count.subscribe((value) => {
  console.log('count changed to', value);
});

unsub(); // stop listening

Untracked reads

Read a signal inside an effect without creating a dependency using untrack():

import { signal, effect, untrack } from '@nexoraaidrishti/runtime';

effect(() => {
  // re-runs when `a` changes, NOT when `b` changes
  a();
  const bVal = untrack(() => b());
  console.log(bVal);
});
Core

Computed Signals

Derived reactive values that automatically update when their dependencies change. Results are memoized — the function only re-runs when inputs change.

Basic derived value

Pass a function to computed(). Any signal reads inside become dependencies. The result is lazily evaluated and cached:

import { signal, computed } from '@nexoraaidrishti/runtime';

const firstName = signal('Jane');
const lastName  = signal('Doe');
const fullName  = computed(() => `${firstName()} ${lastName()}`);

console.log(fullName()); // 'Jane Doe'
firstName.set('John');
console.log(fullName()); // 'John Doe'

Chained computeds

Computeds can depend on other computeds. Dependency graphs propagate efficiently — only stale branches re-evaluate:

const todos     = signal([{ text: 'Buy milk', done: false }]);
const filter    = signal('all');
const pending   = computed(() => todos().filter(t => !t.done));
const completed = computed(() => todos().filter(t => t.done));
const visible   = computed(() =>
  filter() === 'pending'   ? pending()   :
  filter() === 'completed' ? completed() :
  todos()
);
Core

Effects

Side-effectful code that runs whenever its signal dependencies change. Use for DOM side effects, analytics, subscriptions, and network requests.

Basic effect

An effect runs immediately on creation, then re-runs whenever a signal it reads changes. Dependencies are tracked automatically:

import { signal, effect } from '@nexoraaidrishti/runtime';

const theme = signal('dark');

effect(() => {
  document.documentElement.dataset.theme = theme();
});
// Runs immediately, then re-runs on every theme change

Cleanup

Return a cleanup function from an effect to run before the next re-execution or when the effect is disposed:

const query = signal('drishti');
const results = signal([]);

const dispose = effect(() => {
  const ctrl = new AbortController();

  fetch(`/api/search?q=${query()}`, { signal: ctrl.signal })
    .then(r => r.json())
    .then(data => results.set(data));

  return () => ctrl.abort(); // cancels on re-run
});

dispose(); // stop the effect entirely
Core

Batch

Group multiple signal writes into a single atomic update. All effects and computed signals re-evaluate once, after the batch completes.

Batching multiple writes

Without batching, each .set() triggers an immediate flush. Wrapping in batch() defers all notifications until the block returns:

import { signal, computed, effect, batch } from '@nexoraaidrishti/runtime';

const x   = signal(1);
const y   = signal(2);
const z   = signal(3);
const sum = computed(() => x() + y() + z());

effect(() => console.log('sum:', sum())); // sum: 6

batch(() => {
  x.set(10); // no flush yet
  y.set(20); // no flush yet
  z.set(30); // no flush yet
});
// effect re-runs exactly once: sum: 60

Rendering

Renderer

DRISHTI renders directly to the DOM — no virtual DOM, no diffing. h() creates live elements that update in place.

The h() function

h(tag, attrs, ...children) creates a DOM node. Attribute values and children can be signals or reactive functions — they patch the DOM directly when dependencies change:

import { signal, h } from '@nexoraaidrishti/runtime';

const active    = signal(false);
const labelText = signal('Click me');

const btn = h('button', {
  class:   () => active() ? 'btn active' : 'btn',
  onclick: () => active.set(!active()),
},
  () => labelText(),
);
Rendering

show / each

Conditional rendering with show() and efficient keyed list rendering with each().

show() — conditional rendering

import { signal, h, show } from '@nexoraaidrishti/runtime';

const isLoggedIn = signal(false);

const view = show(
  () => isLoggedIn(),
  () => h('div', { class: 'dashboard' }, 'Welcome back!'),
  () => h('div', { class: 'login' }, 'Please sign in'),
);

each() — keyed list rendering

Efficiently re-renders only the items that changed. Provide a key function to identify stable items:

import { signal, h, each } from '@nexoraaidrishti/runtime';

const items = signal([
  { id: 1, name: 'Alpha' },
  { id: 2, name: 'Beta'  },
]);

const list = each(
  () => items(),
  (item) => item.id,
  (item, idx) => h('li', {}, () => item.name)
);

State

State Machines

XState-inspired typed state machines. Define states, transitions, guards, and actions — all reactive via signals.

Creating a machine

Pass a config object with an initial state and a states map. Each state defines its transitions under on:

import { createMachine } from '@nexoraaidrishti/runtime';

const auth = createMachine({
  initial: 'idle',
  states: {
    idle:          { on: { LOGIN:   'loading' } },
    loading:       { on: { SUCCESS: 'authenticated', FAIL: 'error' } },
    authenticated: { on: { LOGOUT:  'idle' } },
    error:         { on: { RETRY:   'loading', CANCEL: 'idle' } },
  },
});

auth.send('LOGIN');    // → 'loading'
auth.send('SUCCESS'); // → 'authenticated'
auth.can('LOGOUT');   // true — check validity before sending

Guards and actions

Add guard functions to conditionally block transitions, and entry/exit hooks for side effects:

const checkout = createMachine({
  initial: 'cart',
  states: {
    cart: {
      on: {
        PROCEED: {
          target: 'payment',
          guard: () => cartItems().length > 0,
        }
      },
      entry: () => trackEvent('cart_view'),
    },
    payment: {
      on: { BACK: 'cart', PAY: 'complete' },
      exit: () => savePayment(),
    },
    complete: {},
  },
});
State

Time Travel

Record every signal mutation and replay, undo, or restore any past state with zero configuration.

enableTimeTravel

Call enableTimeTravel() before mounting your app. All subsequent signal writes are recorded in a ring buffer:

import { enableTimeTravel, signal } from '@nexoraaidrishti/runtime';

const tt    = enableTimeTravel({ maxEntries: 100 });
const count = signal(0);

count.set(1); count.set(2); count.set(3);

// Snapshot and restore
const snap = tt.snapshot();
count.set(999);
tt.restore(snap);  // count() → 3

// Step through history
tt.travel(-1); // undo — count() → 2
tt.travel(+1); // redo — count() → 3

Reactive history UI

const Bar = () => h('div', {},
  h('button', { onclick: () => tt.travel(-1) }, 'Undo'),
  () => `Step ${tt.present()} / ${tt.entries().length}`,
  h('button', { onclick: () => tt.travel(+1) }, 'Redo'),
);

createResource

const UserCard = () =>
  show(() => user.loading(),
    () => h('p', {}, 'Loading...'),
    () => h('div', {}, () => user.data()?.name),

Forms

Schema-driven form state with field-level validation, touched tracking, and submit handling.

createForm

import { createForm, h } from '@nexoraaidrishti/runtime';

const form = createForm({
  email:    { initial: '', validate: v => v.includes('@') || 'Invalid email' },
  password: { initial: '', validate: v => v.length >= 8 || 'Min 8 chars' },

  h('form', { onsubmit: (e) => { e.preventDefault(); form.submit(); } },

    () => form.fields.email.error(),
    h('input', { type: 'password', value: form.fields.password.value }),
    () => form.fields.password.error(),
    h('button', { type: 'submit', disabled: () => !form.valid() }, 'Login'),

Render & Events

Signal Permissions

Fine-grained access control on any signal. Restrict AI agents from reading sensitive state or writing critical values — with a full audit trail.

withPermissions

import { signal, withPermissions, setAIAgent } from '@nexoraaidrishti/runtime';

const salary = withPermissions(signal(95000), {
  aiAccess: 'none',      // AI cannot read or write
  audit: true,           // log every access attempt
});

const theme = withPermissions(signal('dark'), {
  aiAccess: 'read-only', // AI can read but not write
});

setAIAgent('agent-1');    // marks subsequent reads/writes as AI
salary();                 // throws PermissionError
setAIAgent(null);         // back to human context

Access levels: 'read-write' · 'read-only' · 'write-only' · 'none'

Natural Language Queries

drQuery

  { name: 'Bob',   age: 24, active: false },
]);

// result.data()    → [{ name: 'Alice', age: 32, active: true }]
// result.loading() → false
// result.refresh() → re-run the query

Decay Signals

Preferences that forget. Confidence in a learned value halves every halfLife milliseconds — stale choices never lock the UI.

createDecaySignal

import { createDecaySignal } from '@nexoraaidrishti/runtime';

const fav = createDecaySignal({
  initial: 'Electronics',
  halfLife: 7 * 24 * 60 * 60 * 1000, // 7 days
  minConfidence: 0.05,
});

fav.reinforce('Books');       // +0.2 confidence
fav.confidence('Books');       // → 0.2 (decays over time)
fav();                         // → highest-confidence value above minConfidence

Bounded Array Signals

Prevent unbounded array growth. Automatically trims or blocks when the array exceeds maxSize — no more memory leaks from accumulating state.

boundedSignal

import { boundedSignal } from '@nexoraaidrishti/runtime';

const log = boundedSignal([], {
  maxSize: 100,
  strategy: 'drop-oldest',    // 'drop-oldest' | 'drop-newest' | 'throw'
  onBound: (dropped) => console.warn(`Dropped ${dropped.length} entries`),
});

log.push('event-1');  // respects bound
log.isFull();         // → boolean
log.size();           // → current length
